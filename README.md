# Cover Design

Meme「多工序撰稿设计环节链」旗下的短视频封面设计 Skill。它把选题、脚本、真人素材、产品证据和参考视频，转成缩略图可读的封面短句、人物任务、主证据物、构图方案与生图执行稿。

它适用于科创大牛猫、蒸汽电波及其他需要真人出镜的内容账号。运行规则以 [`SKILL.md`](SKILL.md) 为准；这份 README 负责解释设计理念、安装方式和交付边界。

## 它解决什么

常见的科技封面只是在人物旁边堆产品、霓虹和大字，人物没有参与论证，画面也没有告诉观众「点开后会得到什么判断」。Cover Design 把封面视为主页网格中的最小内容承诺：

- 标题只承诺一个能被正文兑现的矛盾或判断。
- 人物必须判断、测量、触碰、持物、指向证据或承受结果。
- 画面只保留一个主证据物，让产品、数据或现场承担可信度。
- 参考账号提供信息组织方法，不提供可以照搬的品牌资产。

## 关键设计理念

### 人物是论证者

衣服、姿势、视线和表情都服务于人物身份。评论者可以直视观众并作出判断；实测者应看向部件并完成具体动作；现场型人物需要与环境发生真实接触。无动作站姿和与内容无关的惊讶脸会被判为素材缺口。

### 人与产品必须形成关系

产品不能只是悬浮在人物旁边。手、视线、身体朝向和空间遮挡要建立可见因果：人在测什么、质疑什么、展示什么，观众应在一秒内看懂。

### 动效被压成静态阅读顺序

来自视频的推进、转场和连续入场不能原样塞进一张封面。Skill 会选择最清楚的一个视觉状态，再用前后景、透视、视线和强调色还原阅读次序。

### 结构探索与单变量测试分开

概念阶段允许比较不同服装、景别、动作和人物—产品关系，用于发现更合适的叙事结构；进入验证阶段后，每轮只改变封面短句、人物动作或证据物占比中的一个变量，避免得到无法归因的测试结果。

### 方法可迁移，品牌不可复制

对影视飓风等参考账号的研究会提取信息密度、人物任务、证据组织和缩略图可读性，不复制其固定框架、字体、色彩和记忆符号。新增账号要先建立最小账号档案，再形成自己的视觉指纹。

### 命题、证据、动作组成三段阅读

封面先提出一个能被正文兑现的命题，中下部用证据窗集中产品、数据或现场，人物再用一个可见动词告诉观众如何理解证据。证据窗可以是局部光区、像素角括号、纸张裁切或真实环境，不要求使用实体边框。

焦段、机位、景深和透视需要说明信息权重。产品评测可以让产品近大远小；人物判断可以让脸和手势先被读取；产业现场则用环境尺度证明「我在这里」。只写「电影感」不能通过方案校验。

## 研究依据

2026-07-31 的影视飓风研究读取了其抖音主页当时加载的 93 条账号作品元数据，并从顶部到加载底部连续检查 17 个作品网格视窗。样本覆盖评测、AI 实验、旅行、纪实、访谈、课程、活动、电商和企业日常。

研究确认其主页统一性来自「命题层→证据窗→人物动作→品牌签名」的稳定协议，同时允许自然视频帧、专题海报和人物纪实使用自己的视觉家族。黑底、白黄大字和红色 `REC` 框只是影视飓风的品牌实现，不是可直接复制的方法。完整记录位于 [`references/filmmaking-hurricane-findings.md`](references/filmmaking-hurricane-findings.md)。

## 四种封面结构

| 结构 | 适用内容 | 人物任务 | 主证据 |
|---|---|---|---|
| 判断对撞型 | 产业判断、商业争议、真假辨别 | 审视、权衡或给出判断 | 产品、图表或争议对象 |
| 实测拆解型 | 汽车、机器人、芯片、相机和 AI 工具 | 操作、测量或指出差异 | 产品部件或测试结果 |
| 产业现场型 | 展会、工厂、城市和供应链 | 进入现场并证明「我在场」 | 真实环境和规模关系 |
| 编辑拼贴型 | 人物故事、商业史和抽象机制 | 解释人物关系或观念冲突 | 档案图、纸张或图表 |

## 安装

把仓库克隆到支持本地 Skills 的客户端目录：

```bash
git clone https://github.com/Emanon4/cover-design.git ~/.codex/skills/cover-design
```

也可以把仓库放入其他 Agent 的 Skills 目录。只要客户端能够发现 `SKILL.md`，即可用自然语言触发，例如：

```text
根据这期脚本，为科创大牛猫设计三套抖音封面，给出推荐方案和生图执行稿。
分析这条参考视频的视觉语言，但不要照抄它的品牌资产。
用同一构图测试两个封面短句，其他条件全部保持不变。
```

## 工作流与交付

Skill 会先确认账号定位和脚本能够兑现的判断，再选择视觉家族，把内容压成「观众疑问、人物身份、一个证据物、点击后答案」。随后交付三套结构有实质差异的方案，并选出一套推荐稿。

每套方案必须写明视觉家族、人物动词、人与证据关系、焦段感、机位、景深、透视和三段阅读顺序。推荐稿还包含 1080×1440 画布、安全区、标题坐标、人物与证据物锚点、分层关系、参考图绑定、固定提示词、本轮单一变量、负面约束、无字底图提示词和后期排版说明。中文标题、数字、产品型号与 Logo 由后期逐字排版，不依赖生成模型书写。

模板位于 [`references/output-template.md`](references/output-template.md)，完整生图交接规则位于 [`references/generation-handoff.md`](references/generation-handoff.md)。

## 生图方式

Skill 不强制使用 API。客户端提供内置图像生成能力时，可以直接使用人物与产品参考图生成无字底图，再完成中文排版；API 或其他生图工具只是可替换的执行层。

需要稳定真人身份时必须提供清晰参考图，并人工比对脸型、年龄、体态和发型。生成结果适合验证构图、服装和动作；正式发布若要求高度还原本人，应按选定姿势补拍真人素材。

## 校验

保存封面方案后运行：

```bash
python3 scripts/validate_cover_plan.py path/to/cover-plan.md
```

校验器会检查三套方案是否齐全、视觉家族是否有效、人物动词和关系字段、镜头语言、三段阅读顺序、封面短句长度、1080×1440 画布以及空泛刺激词。运行内置回归测试：

```bash
python3 scripts/validate_cover_plan.py --self-test
```
