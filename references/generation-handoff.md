# 生图与制作交接

## 素材与真实性

参考图按身份、产品和环境分别绑定用途。本人身份参考用于脸型、年龄感、体态、发型与眼镜；服装、动作和机位是可变项，不能把输入正面照当成已拍摄的动作素材。

真实产品优先使用授权实拍或可靠官方产品图，记录型号和来源。生成示意可表达机制与比喻，不充当拆解证据；混合图注明哪些部件真实、哪些后补。AI 产品界面和输入输出使用同次运行记录，示意图不能装成实际界面。没有真实参考时交付清楚标记的草案，不臆造可核验细节。

## 人物情境

从「目标→动作→作用对象→可见结果」推导服装与镜头。例如协同机制可让人物将两条不同功能路径汇入同一示意系统；要确认连接有工程意义，不能把不同制式接口直接接在一起。若只是类比，用明确的示意手法呈现，不把比喻包装成实测现场。

在选定构图中说明：身体姿势怎样支持动作，表情与视线落在哪里，前景尺度强调什么，哪一层必须清晰。身份一致性靠对照参考照片复核，不承诺模型精确锁脸。需要精确人像时，优先保留原照片主体并调整背景或排版，或提供可执行的补拍姿势。

## 提示词与排版

完整提示词需可回放，至少包含参考图用途、人物情境、主要证据关系、留白依据及禁止伪造的细节。概念探索可以组合改变服装、环境与动作；单变量测试必须列出实际固定的内容和唯一变化，生成后重新比对。

标题默认锁定。保存完整字符串与视觉换行两个字段；断行、字重、字号和局部底色用于解决可读性，不擅自删改文字。字数仅作提醒，英文和产品型号不能因汉字计数而被删除。

优先生成无字底图后排版，需要一体化生成时逐字核对并针对错误修复。必须使用当前环境允许的图像生成或编辑路径。文字排版源文件要和成片一起保存；声称可分层时，交付文件必须实际含独立可编辑层。

画布按目标场景确定。1080×1440 为未指定时的工作默认，不是全平台规范。标题区随素材安排，不强制顶部留白。检查约 270 像素宽的等比例缩略图，以及目标展示区域的裁切；未拿到平台规格时，裁切只能标为模拟。

## 成片记录

每次实际审图后填写清单。JSON 的相对路径以清单所在目录为根；图片检查需要 Pillow（`requirements.txt`）。清单不会自动执行 OCR 或审图，它只检查文件、尺寸、哈希和审阅记录的一致性。

```json
{
  "schema_version": 2,
  "canvas": [1080, 1440],
  "variants": [
    {
      "id": "A",
      "image": "cover-a.png",
      "reviewed_sha256": "实际审阅文件的SHA256",
      "title_transcription": "逐字读出的成片标题",
      "thumbnail": "cover-a-thumb.png",
      "crops": [
        {"file": "cover-a-crop.png", "scene": "主页模拟裁切"}
      ],
      "reviews": {
        "title": {"status": "待验证", "basis": "还未逐字核对", "evidence": []},
        "identity": {"status": "待验证", "basis": "还未对照人物参考", "evidence": []},
        "interaction": {"status": "待验证", "basis": "还未检查手物接触", "evidence": []},
        "evidence_truth": {"status": "待验证", "basis": "还未核查产品与来源", "evidence": []},
        "thumbnail": {"status": "待验证", "basis": "还未看缩略图", "evidence": []},
        "crop": {"status": "待验证", "basis": "还未看目标裁切", "evidence": []}
      }
    }
  ],
  "opening": {
    "status": "待验证",
    "basis": "只有脚本，尚未查看成片",
    "evidence": []
  }
}
```

实际使用时填写真实路径与哈希，不保留示例占位符。所有 review 的 status 取「通过／需修改／待验证／不适用」，basis 写观察到的现象；不适用必须给原因，仅无真人题材且该 variant 写明 `has_presenter: false` 时可将 identity 标为不适用。通过时 evidence 指向实际查看的文件或记录；identity 应包含参考图和成片，thumbnail/crop 指向相应预览。opening 通过时另填 `source`（视频来源）与 `time_range`（实际秒数区间，如 `[0, 3]`），不以脚本代替实际视频。

生图后可分批交付：清单仅列出本次导出的方案，遗漏方案会显示待交付提示。单变量测试宣布准备发布时，两版都必须完成。

运行 `--artifacts artifacts.json` 可查看草案状态；运行 `--ready` 要求所有适用图片检查和实际开场检查均完成。哈希变动会使旧审阅失效。文件存在或哈希正确不证明审阅结论真实，执行者仍须实际看图、看视频。

最终交付包含用户要求的成片、完整提示词、底图（若使用）、排版源文件和检查记录。缺什么明确说明，不将方案校验通过写成成片或发布效果已验证。
