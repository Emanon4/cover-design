# 封面方案 v2

下面是机器可检查的最小结构。字段值写在同一行；一个想法只填一次。纯建议无需为了套模板伪造素材或成片。具体完整样例见 `tests/fixtures/`。

## 输入判断

- 方案版本：2
- 工作模式：单稿
- 目标账号：账号名称。
- 账号定位版本：来源日期或本次临时定位。
- 核心判断：正文实际回答的问题。
- 封面承诺：观众因何点开，能够获得什么。
- 内容依据：脚本段落、素材编号或来源；缺失时明确说明。
- 开场依据状态：脚本已有
- 开场兑现点：已有台词与镜头，或明确标为建议的衔接。
- 标题策略：锁定
- 原始标题：用户提供的完整标题；没有指定时将策略改为「可提案」。
- 画布：1080×1440
- 展示场景：主页单卡；采用什么裁切依据，未确认的规格注明设计假设。

「成片已核验」另填 `开场核验依据`，写实际视频文件及时间段。没有视频时保持「脚本已有」或「建议补拍」，不能把建议改写成已实现。

## 方案 A

- 封面短句：完整可见标题，保留原始标点，不用斜线表示换行。
- 排版换行：用「｜」表示视觉换行，仅作为排版说明。
- 点击动机：正文已有的信息缺口。
- 视觉家族：本题适用的明亮实测、编辑海报、自然现场等，不限枚举。
- 人物目标：人物此刻试图说明或完成什么。
- 人物动词：一个具体动作，如接入、比较、追问。
- 作用对象：动作落在什么位置或对象上。
- 可见结果：不靠说明文字，观众能够看出的关系或结果。
- 人物设计：服装、姿势、表情及视线如何服务目标。
- 主要证据关系：可以是单物、比较、输入输出或协同系统。
- 素材性质：实拍／真实截图／官方素材／生成示意／混合／待补素材。
- 素材来源：对应来源；混合时逐项写明性质及用途。
- 真实性边界：画面能证明什么，哪些只是示意或尚未验证。
- 构图与镜头：人物、标题、主要证据的阅读顺序，以及尺度和清晰层次。

单稿只保留 A。概念探索按需求增加 B、C 等，每版加 `差异说明`，解释叙事变化；相同标题可以保留。多方案增加 `## 推荐`，填写 `推荐方案`（A 等编号）与 `推荐理由`。不要在 C 后面混入执行稿字段，覆盖 C 自己的内容。

## 测试设计

仅「单变量测试」需要此节，且保留两版：

- 唯一变量：封面短句／人物动作／证据占比。
- 固定条件：相同素材版本、构图、色彩等。
- 对照条件：同一内容、同一入口和观察窗口；不能随机分配时标明观察研究。
- 指标口径：点击率的曝光与点击分母，匹配来源的早期留存；没有数据则待验证。

两版各填写 `变量取值`。不同变量对应允许变化的字段见校验器；真实图像仍需视觉核对，文字一致不代表图像已固定。

## 制作交接

仅执行制作时填写；使用 [generation-handoff.md](generation-handoff.md)：

记录参考图绑定、固定与可变条件、完整生图提示词、标题排版、裁切方案、预期输出文件和可编辑源文件。用户指定数量优先，不要求每个概念都生成成片。

## 验收记录

方案阶段写「成片待生成／待验证」，不要预先勾选通过。完成后把逐项视觉观察写入独立 `artifacts.json`，通过 `--artifacts` 与实际文件一起检查。发布后的点击／留存记录与图片验收分开保存。
